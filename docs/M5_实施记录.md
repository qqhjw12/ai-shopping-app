## 一、本次交付（M5 加固）

在不改动任何业务能力的的前提下，为 `ai-gateway` 补齐生产级加固项，全部遵循「双模式」契约（local 可在此沙箱验证，docker 在你本机切真实服务）。

| 加固项 | 实现 | 文件 |
|--------|------|------|
| **结构化日志** | JSON 行日志（ts/level/msg/reqId/ip/method/path/status/durationMs），敏感头（Authorization/X-API-Key/Cookie）自动脱敏，错误走 stderr 便于容器采集 | `src/logger.js` |
| **请求 ID 贯穿** | 每请求生成 UUID，写入 `X-Request-Id` 响应头 + 所有日志，便于链路追踪 | `src/middleware.js` `attachContext` |
| **CORS 显式来源** | 仅允许 `CORS_ORIGINS` 白名单匹配；`*` 仅在显式配置时生效并告警；其余来源**不返回 ACAO**（浏览器即拦截） | `src/middleware.js` `applyCors` |
| **API Key 鉴权** | `AI_GATEWAY_API_KEY` 设置后，所有业务接口（除 `/health`、`/ready`）需 `X-API-Key` 或 `Authorization: Bearer`；未设置则开放（仅演示/内网） | `src/middleware.js` `checkAuth` |
| **按 IP 限流** | 固定窗口：每 IP `RATE_LIMIT_PER_MIN` 次，`Retry-After` 提示；`TRUST_PROXY` 时取 `X-Forwarded-For` 真实 IP | `src/middleware.js` `checkRateLimit` |
| **健康检查** | `GET /health`（存活）+ `GET /ready`（就绪：探向量库/搜索库/Dify 配置，docker 模式额外校验） | `src/server.js` |
| **优雅停机** | `SIGTERM`/`SIGINT` → 停止接新连接 → 排空在途连接 → `exit(0)`；10s 兜底强退，防僵尸 | `src/server.js` `shutdown` |
| **启动期告警** | 缺 `AI_GATEWAY_API_KEY` 或未显式配 `CORS_ORIGINS` 时打印 warn | `src/config.js` `startupWarnings` |

## 三、本地冒烟（已验证，沙箱 local 模式）

| 项 | 命令/场景 | 结果 |
|----|-----------|------|
| 存活探针 | `GET /health` | `status:ok`，含 runMode/embedding/向量库计数 ✅ |
| 就绪探针 | `GET /ready` | `status:ready`，`deps.ready:true` ✅ |
| 默认无 key | `POST /api/ai/chat`（无 key） | HTTP 200 ✅ |
| 显式 CORS | `OPTIONS` + `Origin: http://localhost:5500` | 返回 `Access-Control-Allow-Origin: http://localhost:5500` ✅ |
| 鉴权拦截 | `AI_GATEWAY_API_KEY=secret`，无 key 调业务接口 | HTTP 401，带 `reqId` ✅ |
| 鉴权放行 | 同上，带 `X-API-Key: secret` | HTTP 200 ✅ |
| 探针免鉴权 | 带 key 模式 `GET /health` | HTTP 200（探针跳过鉴权）✅ |
| 限流触发 | `RATE_LIMIT_PER_MIN=2` 连打 5 次 | 前 2 次 200，第 3–5 次 429 + `Retry-After: 60` ✅ |
| 结构化日志 | 任意请求后看 `access` 行 | `{"level":"info","msg":"access","reqId":"…","ip":"::ffff:127.0.0.1","method":"POST","path":"/api/ai/chat","status":200,"durationMs":2}` ✅ |
| 前端对接 | `web/app.js` 含 `API_KEY` 常量，401/429 友好提示 | 语法通过 ✅ |

> ⚠️ **优雅停机（SIGTERM）未能在本沙箱实测**：本沙箱的 `kill` / `process.kill` 不向后台进程投递信号（连最简 `process.on('SIGTERM')` 都收不到，进程以 143 被回收）。代码采用 Node 标准优雅停机范式（`server.close` + 排空 + `process.exit(0)`），在你本机 Docker/systemd 环境下可正常工作。验证方式：`docker stop` 触发 SIGTERM，观察日志出现 `shutdown` 行且 `exit 0`。

## 四、你本机怎么验

```bash
cd D:\shapp
# 1) 设密钥与来源（.env）
cp .env.example .env
#   写入 AI_GATEWAY_API_KEY=你的密钥
#   写入 CORS_ORIGINS=http://localhost:5500   # 生产改成你的域名，严禁 '*'

# 2) local 模式快速验（无需 Docker）
cd ai-gateway && AI_GATEWAY_API_KEY=secret node src/server.js
curl -i -H 'X-API-Key: secret' -X POST http://localhost:8080/api/ai/chat -d '{"message":"运费多少"}'
curl -i http://localhost:8080/ready

# 3) docker 一把梭（compose 已透传 M5 变量）
docker compose up -d
docker compose -f docker-compose.dify.yml up -d
# 优雅停机： docker stop shopping-ai-gateway  -> 日志末行应见 shutdown
```

## 五、生产级注意事项（简历可写）

1. **密钥不落静态前端**：`web/app.js` 的 `API_KEY` 仅本地联调用；真实部署请把网关放反向代理（nginx）后，由代理注入 Key，前端不直接持有。
2. **CORS 白名单**：绝不用 `*`，按真实域名配置；已支持凭据（具体来源 + `Credentials: true`）。
3. **限流**：当前是单实例内存桶；多副本需换 Redis 集中计数（如 `rate-limit-redis`）。作品集规模够用。
4. **健康探针**：`/ready` 在 docker 模式会校验 Dify 关键 Key 是否就绪，K8s 可挂 `readinessProbe`。
5. **日志**：结构化 JSON 已就绪，接 Loki/ELK 直接采集；敏感头已脱敏，符合基本合规。
6. **HTTPS**：生产前面挂 nginx/Traefik 终止 TLS，网关自身只跑 HTTP（内网）。
